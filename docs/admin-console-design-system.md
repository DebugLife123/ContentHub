# ContentHub 管理后台设计规范（Admin Console）

> 版本 v1.0 ｜ 实现位置：`frontend/src/components/admin/` + `frontend/src/styles/admin-system.scss`
> 入口：站点顶栏「管理后台 ↗」→ `/admin`

---

## 一、定位

管理后台是**独立整屏工作区**，不是网站的一个普通页面：

- 进入 `/admin/*` 后，站点头部与页脚**整体让位**，由控制台外壳接管整屏；
- 模块切换只替换中间内容区，外壳（侧边栏 / 顶栏）保持不动，不重新挂载；
- 与前台共用品牌基因（暖纸底、墨色、橙点缀、DM Mono 微标签、衬线斜体），但骨架换成"控制台"。

### 为什么不做成普通页面
原先 8 个管理页各自套在站点头部/页脚里，出现三个问题：
1. 层级混乱——"网站里的管理页"不像一个独立工作区；
2. 导航分散——顶栏 hover 下拉要装 8 个模块，越加越长；
3. 样式重复——每个页面各自复制一遍表头、表格、状态标签的 CSS，改一处要改八处。


## 四、进入过场（Loading）

点击「管理后台」后播放一段 **820ms** 的过场，然后与内容交叉淡入：

| 时间 | 内容 |
|---|---|
| 0ms | 墨色整屏；品牌标 + `ADMIN CONSOLE`；一条 2px 橙色进度线开始填充 |
| 270ms | 文案：正在校验管理员权限… → 装载管理模块… |
| 610ms | 文案：装载管理模块… → 就绪 |
| 820ms | 遮罩开始淡出（300ms），同时内容区从 `opacity: 0` 淡入（340ms） |

设计纪律：
- **短、静、有终点**。不做循环动画、不做假进度条停留，不让过场盖住真实等待；
- 只在**进入管理后台**时播放一次（子模块切换不重播，因为外壳不重新挂载）；
- 尊重 `prefers-reduced-motion: reduce`——直接跳过，不做任何动画。

## 五、侧边栏

- 品牌区：`ContentHub` 标识 + `ADMIN CONSOLE` 字样，底部 1px 分隔线；
- 分组标签：`OVERVIEW / CONTENT / SKILL MARKET / PLATFORM`，DM Mono 9px、字距 0.22em、白色 28% 透明度；
- 导航项：模块编号（`00`–`08`，DM Mono）+ 中文名；
  - hover：文字转白 + 5% 白色底；
  - 激活：左侧 2px 橙色竖线 + 13% 橙底，编号同步转橙；
- 待处理徽标：内容审核 / 创作者申请显示橙色胶囊数字（>99 显示 `99+`），**为 0 时不显示**；
- 侧栏底部：管理员身份（头像首字母 + 昵称 + 角色）+ 「返回站点 ↗」。

## 六、页头与内容规范

### 页头 `AdminPageHeader`
| 元素 | 规格 |
|---|---|
| eyebrow | DM Mono 10px，字距 0.16em，如 `ADMIN / CONTENT REVIEW` |
| 标题 | Manrope 750 27px，字距 -0.035em |
| 强调词 | 衬线斜体（Noto Serif SC 600），橙色 `--art-accent` |
| 说明 | 12.5px / 1.75，`--muted`，最多 560px |
| 主操作 | 右侧 `#actions` 插槽（如「新增分类」） |

> 尺寸刻意从台前的 54px 展示型标题收敛到 27px：控制台里页头是"路标"，正文数据才是主角。

### 工具条 `.admin-toolbar`
筛选控件（输入框 / 下拉）+ 主筛选按钮 + 反馈文字，一行 flex 自动换行。反馈文字用 `.admin-flash`（`.is-ok` / `.is-error`），**不用弹窗打断**。

### 数据表 `.admin-table`
- 表头：DM Mono 10px、字距 0.1em、`--muted`，底部 **1px 墨色实线**（控制台感的关键）；
- 行：`padding: 15px 14px`，1px 暖灰分隔线，最后一行不画线；
- **行 hover**：4.5% 橙底 + 首列内侧 2px 橙色标记——
  这是全表唯一的"活气"来源，用内阴影而非投影，不违反"不堆阴影"的纪律；
- 空态 `.admin-empty`：`···` 符号 + 一句解释，不用插画；
- 加载态 `.admin-loading`：`LOADING…` DM Mono 字距 0.14em；
- **长文本列**：`.admin-cell-clip`（限宽 340px + 两行截断）。
  注意它用 `display: -webkit-box`，**必须挂在该单元格内层的 `<div>` 上，不能直接加在 `<td>`**——
  直接加在 `td` 会覆盖 `display: table-cell`，整张表布局会塌掉。

### 标签 `.admin-tag`
统一 5 种变体，10px DM Mono + 1px 描边 + 6% 底色：

| 变体 | 语义 | 用例 |
|---|---|---|
| `is-on` | 正常 / 已通过 | 已发布、启用、上架 |
| `is-off` | 终止 / 已失效 | 已驳回、已下架、已禁用 |
| `is-warn` | 待处理 | 待审核、管理员角色 |
| `is-info` | 中性信息 | 免费、普通分类 |
| `is-accent` | 品牌强调 | 需要特别注意的项 |

### 行内操作 `.admin-actions`
DM Mono 11px + 下划线（22% 墨色），hover 转橙；危险操作加 `.is-danger` 转红。**不用按钮**——表格里堆按钮会让 8 行数据变成 24 个控件。

## 七、概览页（`/admin`）

控制台落地页，回答"现在有什么要我处理"：

1. **五项指标**：待审核内容 / 注册用户 / 评论总数 / 内容分类 / 订阅套餐。
   指标卡是 1px 描边的网格（用 `gap: 1px` + 底色做分隔线），**不用圆角卡片 + 投影**；
   每张卡整体是链接，可直接跳进对应模块。
2. **待审核队列**：最新 5 条待审核内容 + 「去审核」直达。
3. **模块直达**：5 个模块的编号 + 名称 + 一句话说明。

容错：5 个统计各发各的请求、各自 `try/catch`。任一接口失败只让对应数字显示 `—`，
不影响整页可用（后端未启动时仍能看到外壳与入口）。

## 八、组件架构

```
components/admin/
├── AdminLayout.vue      ← 整屏外壳：侧边栏 + 顶栏 + 内容区 + 过场 + 模块切换过渡
├── AdminBoot.vue        ← 进入过场动画（自管显隐，走完 emit done）
└── AdminPageHeader.vue  ← 共享页头（eyebrow / title / accent / description + actions 插槽）
styles/admin-system.scss ← 全部管理端 token 与通用 class
views/admin/Overview.vue ← 控制台概览
views/admin/*.vue        ← 9 个业务模块页（只写本页独有样式）
```

### 路由接线
```ts
{
  path: '/admin',
  component: AdminLayout,
  meta: { title: '管理后台', layout: 'admin', requiresAuth: true, roles: ['ADMIN'] },
  children: [ /* 子路由继承 requiresAuth 与 roles，权限语义不变 */ ],
}
```
`App.vue` 依据 `route.meta.layout === 'admin'` 决定是否渲染站点头部与页脚。

## 九、响应式

| 断点 | 行为 |
|---|---|
| ≥1181px | 侧栏常驻，内容区留白 36px |
| 1024–1180px | 留白收窄 24px，指标字号下调 |
| ≤1023px | 侧栏转为**抽屉**（左上「☰ 模块」唤出 + 遮罩关闭），页头主操作换行 |
| ≤767px | 留白 16px，指标两列，表格字号与内边距收窄，隐藏顶栏日期 |

## 十、纪律清单

**做**：1px 线分层次 · 留白分组 · DM Mono 做微标签 · 橙色只用于强调与激活 · 数字用大字号 Manrope。

**不做**：卡片 + 投影堆叠 · 渐变背景 · 圆角泛滥 · 每行都放按钮 · 弹窗报错 · 循环加载动画 · 侧栏塞二级菜单树。

> 判断标准：一个功能要不要加视觉元素，先问"它是否帮助管理员更快看清数据"。
